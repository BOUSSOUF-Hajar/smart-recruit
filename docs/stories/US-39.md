# US-39 — Notes internes

Phase 7 · SHOULD · 3 points · dépend de US-31 · réf. F-NOTE-01, RG-23

## 1. Objectif et critères

| Critère d'acceptation | Preuve |
| --- | --- |
| Note de 1 à 5 000 caractères, avec nom et date, visible de toute l'entreprise | `NoteIT.noteIsSharedWithColleaguesButOnlyItsAuthorChangesIt` ; note vide → 400 ; `ck_note_content` |
| Note d'un collègue → modification et suppression refusées | Même test (403 `ACCESS_DENIED`) ; `NoteTest` ; boutons affichés seulement pour ses notes (`mine`) |
| Note modifiée → mention « modifiée » et date | Même test (`edited: true`) ; `NotesPanel` |
| Aucune note dans les réponses destinées au candidat | `notesStayInsideTheCompanyAndAreNeverShownToTheCandidate` (réponses brutes ; 403 sur l'endpoint des notes ; 404 pour une autre entreprise) |
| (ajout) Suppression logique, compteur et historique | Même premier test (`notesCount`, entrée `NOTE_ADDED`, note supprimée introuvable) |

## 2. Choix techniques

| Choix | Alternative écartée | Raison |
| --- | --- | --- |
| Notes dans le module Candidatures | Module dédié | Elles n'existent que rattachées à une candidature ; même contrôle de propriété (`ApplicationAccess`) |
| 404 hors entreprise, 403 pour la note d'un collègue | 404 partout | La note est visible de l'équipe : son existence n'est pas un secret (docs/api.md §7) |
| Dates gérées par l'entité, pas par l'audit JPA | `@CreatedDate` / `@LastModifiedDate` | « Modifiée » = `updatedAt > createdAt` exige deux valeurs strictement égales à la création |
| Historique : « note ajoutée » avec son identifiant, sans le contenu | Copie du contenu | Le contenu peut changer ou être supprimé ; l'historique, lui, est immuable |
