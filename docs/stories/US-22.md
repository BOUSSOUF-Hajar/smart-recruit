# US-22 — Modifier une offre

Phase 5 · MUST · 3 points · dépend de US-21 · réf. F-JOB-02, RG-17

## 1. Objectif et critères

| Critère d'acceptation | Preuve |
| --- | --- |
| DRAFT ou PUBLISHED modifiable ; modification d'une offre publiée auditée | `JobOfferIT.publishedOfferEditIsAuditedAndStaleVersionIsRefused` (ligne `JOB_UPDATED`) |
| CLOSED ou ARCHIVED : refus, formulaire en lecture seule | `closedOfferIsReadOnly` (409 `INVALID_STATE`) ; `JobOfferLifecycleTest.closedAndArchivedOffersAreReadOnly` ; `isEditable` (spec) qui désactive le formulaire |
| Offre d'une autre entreprise → 404 | `offerOfAnotherCompanyIsNotFound` (lecture, modification et actions) |
| (ajout) Modification concurrente détectée | Même test que l'audit : version périmée → 409 `CONCURRENT_MODIFICATION` ; l'écran propose de recharger |
| (ajout) Une offre publiée garde au moins une compétence requise | `publishedOfferMustKeepARequiredSkill` |

## 2. Choix techniques

| Choix | Alternative écartée | Raison |
| --- | --- | --- |
| `findByIdAndCompanyId` → 404 | 403 « pas votre offre » | Ne révèle pas l'existence d'une offre d'un concurrent (RG-06) |
| Verrou optimiste : `version` envoyée par le client et comparée avant `@Version` | Dernier écrit gagne | Deux recruteurs de la même entreprise peuvent éditer la même offre |
| Audit seulement si l'offre est publiée | Audit de chaque brouillon | Ce qui compte est ce que les candidats ont pu lire ; un brouillon change sans cesse |
| `PUT` complet (remplacement des compétences) | `PATCH` | Le formulaire envoie toujours l'offre entière ; pas de sémantique de fusion à documenter |

## 3. Question d'entretien

**« Pourquoi ne pas bloquer la modification d'une offre publiée qui a déjà des candidatures ? »** Corriger une coquille reste utile. L'audit garde la trace ; les règles plus fortes (ne pas changer les compétences requises après les premières candidatures) seront évaluées avec le matching de la phase 8.
