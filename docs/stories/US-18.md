# US-18 — Télécharger mon CV

Phase 4 · MUST · 2 points · dépend de US-17 · réf. F-CAND-05

## 1. Objectif et critères

| Critère d'acceptation | Preuve |
| --- | --- |
| Fichier servi par un endpoint authentifié, téléchargement forcé | `ResumeIT.downloadIsForcedAndAuthenticated` (`Content-Disposition: attachment`, nom UTF-8, `no-store`, 401 sans token) |
| CV d'un autre candidat → 404 | Par construction : `/candidates/me/resume/file` ne prend aucun identifiant ; le CV vient du token |
| Fichier absent du disque → 404 et alerte dans les logs, sans chemin exposé | `fileMissingOnDiskGives404AndAnAlertWithoutPath` |

## 2. Choix techniques

| Choix | Alternative écartée | Raison |
| --- | --- | --- |
| Téléchargement par `HttpClient` puis `URL.createObjectURL` | Lien `<a href>` direct | Un lien ne porte pas le token ; le CV n'a jamais d'URL publique (RG-07) |
| `attachment` + `X-Content-Type-Options: nosniff` (Spring Security) + CSP | Affichage dans le navigateur | Le PDF n'est jamais interprété dans le contexte de l'application |
| `filename*=UTF-8''…` | Nom ASCII seul | « CV Salma été.pdf » garde ses accents |
| Log avec l'identifiant du CV, pas le chemin | Trace complète | Le chemin du stockage n'a rien à faire dans un log lisible par l'exploitation |

## 3. Questions d'entretien

**« Pourquoi pas une URL signée vers le fichier ? »** Utile avec un stockage objet (S3) pour décharger l'API ; ici les fichiers sont petits et locaux, et passer par l'API garde un seul point de contrôle d'accès, audité pour les recruteurs en phase 6.
