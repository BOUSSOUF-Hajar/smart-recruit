# US-33 — Rejeter avec motif

Phase 6 · MUST · 3 points · dépend de US-32 · réf. RG-14, RG-22, RG-23

## 1. Objectif et critères

| Critère d'acceptation | Preuve |
| --- | --- |
| Non finale → REJECTED avec motif et commentaire ; entretiens planifiés annulés | `RecruiterApplicationIT.rejectionNeedsAReasonIsKeptInternallyAndIsFinal` ; `ApplicationWorkflowTest.rejectionKeepsReasonAndCommentAndWithdrawalKeepsTheCandidateComment`. Annulation des entretiens : événement publié, écouteur en phase 7 (voir US-29) — **fait en phase 7** : `ApplicationOutcomeListener` (module Entretiens), testé par `InterviewIT.rejectingTheApplicationCancelsItsScheduledInterviews` et `withdrawalCancelsScheduledInterviewsToo` |
| Sans motif → `REJECTION_REASON_REQUIRED` | Même test (422) ; `rejectionRequiresAReason` ; `StatusDialog` spec ; contrainte `ck_application_rejection` vérifiée par une mise à jour SQL directe |
| Confirmation avant l'action définitive | `ApplicationDossierPage.changeStatus` : second dialogue « Rejeter la candidature ? » ; le dialogue de statut annonce déjà « Ce choix est définitif » (`StatusDialog` spec) |
| (ajout) Motif jamais visible du candidat | `CandidateApplicationIT.candidateSeesSimplifiedStatusesAndNothingInternal` |

## 2. Choix techniques

| Choix | Alternative écartée | Raison |
| --- | --- | --- |
| Motif à la fois dans le workflow (422), le DTO, et la base (`(status = 'REJECTED') = (rejection_reason IS NOT NULL)`) | Contrôle applicatif seul | La contrainte refuse aussi un motif sur une candidature non rejetée |
| Motif et commentaire copiés dans l'historique | Seulement sur la candidature | La chronologie raconte la décision complète, et l'historique est immuable |
| Confirmation en deux temps (choix, puis confirmation) | Un seul dialogue | Le rejet est la seule transition finale fréquente ; une erreur de clic coûte cher |
