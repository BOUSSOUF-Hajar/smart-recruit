# US-17 — Téléverser mon CV

Phase 4 · MUST · 8 points · dépend de US-13 · réf. F-CAND-03, RG-07, RG-08

## 1. Objectif et critères

| Critère d'acceptation | Preuve |
| --- | --- |
| PDF valide ≤ 5 Mo → CV actif, nom, taille et date affichés | `ResumeIT.validPdfBecomesTheActiveResume` ; `ResumePanel` |
| Fichier renommé en `.pdf` → `FILE_INVALID_TYPE` | `textFileRenamedAsPdfIsRefusedAndNothingIsStored` ; `ResumeInspectorTest` |
| Plus de 5 Mo → `FILE_TOO_LARGE`, côté frontend puis backend | `fileAboveFiveMegabytesIsRefused` ; `file-upload.spec` ; limite multipart `5MB` |
| Nom avec `../` → fichier stocké sous un nom UUID, nom d'origine nettoyé en métadonnée | `pathInTheFileNameIsDroppedAndTheFileGetsAUuidName` ; `OriginalFilenameTest` ; `LocalFileStorageTest.refusesKeysThatCouldEscapeTheRoot` |
| Nouveau CV : l'ancien n'est plus actif mais reste lié | `newResumeReplacesTheOldOneWhichIsKept` ; index unique partiel `uk_resume_active_candidate` |
| Échec en base après écriture du fichier → fichier supprimé | `ResumeServiceTest.storedFileIsDeletedWhenTheDatabaseFails` |
| En plus : PDF protégé par mot de passe ou endommagé → `FILE_UNREADABLE` | `passwordProtectedPdfIsRefused` ; `ResumeInspectorTest` |

| Fichier | Rôle |

## 3. Choix techniques

| Choix | Alternative écartée | Raison |
| --- | --- | --- |
| Signature binaire + ouverture par PDFBox | Extension ou type MIME seuls | Le navigateur déduit le type de l'extension : un `.txt` renommé arrive en `application/pdf` |
| Fichier écrit avant la base, supprimé si la base échoue | Base d'abord | Une ligne en base sans fichier casserait le téléchargement ; un fichier orphelin est sans effet et sera nettoyé (V2) |
| Aucune écriture de fichier dans la transaction | `@Transactional` sur tout le téléversement | Une connexion du pool ne reste pas bloquée pendant l'écriture disque |
| Ancien CV désactivé et vidé (`saveAndFlush`) avant l'insertion | Une seule écriture finale | L'index unique partiel serait violé si l'INSERT passait avant l'UPDATE |
| Clé UUID générée par le stockage, vérifiée par expression stricte | Nom d'origine nettoyé comme chemin | Aucun nom fourni par le client ne touche le système de fichiers |
| Écriture dans un fichier temporaire puis renommage atomique | Écriture directe | Un lecteur ne voit jamais un fichier à moitié écrit |
| Barre de progression indéterminée | Progression réelle | `withFetch()` ne remonte pas la progression d'envoi ; 5 Mo partent en quelques secondes |
| Code `FILE_UNREADABLE` pour un PDF chiffré | L'accepter | Ni le recruteur ni l'IA (phase 8) ne pourraient le lire |

## 4. Commandes

```bash
curl -i -X POST localhost:8080/api/v1/candidates/me/resume \
  -H "Authorization: Bearer $TOKEN" -F "file=@cv.pdf;type=application/pdf"
```

## 5. Erreurs probables

| Symptôme | Cause | Solution |
| --- | --- | --- |
| 413 sans corps JSON en production | Nginx coupe avant Spring | `client_max_body_size 6m;` (phase 11) |
| `AccessDeniedException` au démarrage | Dossier `STORAGE_ROOT` non inscriptible | Droits du volume Docker |
| 409 `CONCURRENT_MODIFICATION` au téléversement | Deux envois simultanés : le second heurte l'index partiel | Recharger, le premier CV est actif |

## 6. Questions d'entretien

**« Le disque et la base ne partagent pas de transaction : comment restez-vous cohérent ? »** Ordre choisi (fichier puis base), compensation si la base échoue, et nettoyage périodique des orphelins pour le cas où la compensation échoue elle-même. On accepte un fichier orphelin, jamais une ligne sans fichier.

**« Comment vous protégez-vous de la traversée de répertoires ? »** Le nom d'origine n'est jamais un chemin : la clé est un UUID généré par le serveur, vérifié par une expression stricte, et le chemin résolu doit rester sous la racine.
