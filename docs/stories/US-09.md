# US-09 — Se déconnecter

Phase 3 · MUST · 1 point · dépend de US-08 · réf. F-AUTH-04

## 1. Objectif et critères

| Critère d'acceptation | Preuve |
| --- | --- |
| Refresh token révoqué, cookie effacé, token oublié, retour à la connexion | `AuthFlowIT.logoutRevokesTheSessionClearsTheCookieAndIsIdempotent` ; `auth.service.spec` (destination `/login`) |
| Backend injoignable → déconnexion locale quand même | `auth.service.spec` : « ferme la session locale même si le serveur est injoignable » |

## 2. Fichiers

`AuthService.logout`, `AuthController.logout` (cookie `Max-Age=0` sur le même chemin), `RefreshCookies.clear`, frontend `AuthService.logout` et menu utilisateur de l'`AppLayout`.

## 3. Choix techniques

| Choix | Alternative écartée | Raison |
| --- | --- | --- |
| Endpoint public, idempotent, toujours 204 | Exiger un token valide | On doit pouvoir se déconnecter avec un token expiré ; un second appel ne doit pas échouer |
| Cookie effacé même si le jeton est inconnu | Effacer seulement en cas de succès | Le navigateur ne garde jamais un cookie mort |
| Access token non révoqué côté serveur | Liste noire des JWT | Il expire en 15 min ; une liste noire réintroduirait un état à consulter à chaque requête |

## 4. Questions d'entretien

**« L'access token reste valable 15 minutes après la déconnexion : est-ce grave ? »** Il n'est plus nulle part côté client (mémoire effacée). Pour un vol avant déconnexion, la fenêtre est bornée à 15 minutes ; c'est le compromis assumé des tokens sans état.
