# US-12 — Limiter la force brute

Phase 3 · SHOULD · 3 points · dépend de US-07 · réf. F-AUTH-02 A3, ENF-SEC-09

## 1. Objectif et critères

| Critère d'acceptation | Preuve |
| --- | --- |
| 5 échecs en 15 min pour un email → 6e tentative refusée `RATE_LIMITED`, même avec le bon mot de passe | `AuthFlowIT.sixthFailedAttemptWithinFifteenMinutesIsRateLimited` (avec `Retry-After`) |
| 15 minutes plus tard, connexion à nouveau possible | `SlidingWindowRateLimiterTest.oldEventsLeaveTheWindow` (horloge simulée) |
| Inscriptions limitées à 10 par IP et par heure | `AuthRateLimits`, configuration `smartrecruit.security.rate-limit` |

## 2. Fichiers

`shared/security/SlidingWindowRateLimiter.java` (fenêtre glissante en mémoire), `identity/application/AuthRateLimits.java` (connexion par email, inscription par IP), `RateLimitExceededException` + en-tête `Retry-After` dans le `GlobalExceptionHandler`, message de la page de connexion à partir de `retryAfterSeconds`.

## 3. Choix techniques

| Choix | Alternative écartée | Raison |
| --- | --- | --- |
| Compteur par email pour la connexion | Par IP | Protège un compte précis même contre une attaque répartie sur plusieurs adresses |
| Compteur remis à zéro après un succès | Fenêtre fixe | Un utilisateur qui se trompe deux fois puis réussit n'est pas pénalisé ensuite |
| Fenêtre glissante | Fenêtre fixe (par quart d'heure) | Pas de rafale possible à cheval sur deux fenêtres |
| En mémoire (`ConcurrentHashMap.compute`) | Bucket4j + Redis | Une seule instance de l'API ; le stockage pourra être partagé sans changer les appelants |
| Tentative bloquée auditée (`RATE_LIMITED`) | Rien | Une attaque devient visible dans le journal |

## 4. Erreurs probables

| Symptôme | Cause | Solution |
| --- | --- | --- |
| Tests d'intégration en 429 aléatoires | Limiteurs partagés par le contexte Spring | Emails uniques, IP aléatoire pour les inscriptions (`AuthFlowIT.randomIp`) |
| Limite contournée derrière un proxy | Toutes les requêtes ont l'IP du proxy | `server.forward-headers-strategy=native` derrière Nginx (phase 11) |

## 5. Questions d'entretien

**« Un attaquant peut-il bloquer le compte d'un autre ? »** Pendant 15 minutes, oui : c'est le prix de la protection. Le blocage est temporaire et ne touche que la connexion par mot de passe ; les sessions en cours continuent.
