# US-45 — Tableau de bord candidat

Phase 9 · MUST · 3 points · dépend de US-28, US-35 · réf. D8

## 1. Objectif et critères

| Critère d'acceptation | Preuve |
| --- | --- |
| Nombre de candidatures par libellé simplifié, prochains entretiens, état du CV | `DashboardIT.candidateSeesSimplifiedStatusesUpcomingInterviewsAndResume` : SCREENING et SHORTLISTED cumulés sous IN_REVIEW, le mot SHORTLISTED absent de la réponse brute, entretien annulé ou passé exclu ; `candidate-dashboard.page.spec.ts` |
| Sans CV, un appel à l'action invite à le téléverser | Spec : bloc `.cta` avec un lien vers `/candidate/profile?tab=4` (onglet CV) ; absent quand le CV existe |

## 2. Fichiers

- Backend : `reporting/application/DashboardService.candidate`, `DashboardQueries.applicationsByInternalStatus` et `candidateInterviews` ; `application/api/CandidateStatus.java` (déplacé du domaine vers l'API pour que `reporting` traduise les statuts) ; `candidate/api/ProfileOverview.java` et `CandidateDirectory.overview`.
- Frontend : `features/candidate/pages/candidate-dashboard.page.ts` et sa spec.

## 3. Choix techniques

| Choix | Alternative écartée | Raison |
| --- | --- | --- |
| Statuts internes comptés en SQL, traduits en libellés candidat par le serveur | Traduction dans le navigateur | Même règle que la vue candidat d'une candidature (api.md §5) : SHORTLISTED ne doit jamais apparaître dans la réponse |
| Complétude et état du CV demandés au module Candidats (`CandidateDirectory.overview`) | Requête SQL directe dans `reporting` | Le calcul de complétude est une règle métier du module Candidats (US-14) : la dupliquer en SQL la ferait diverger |
| Cinq prochains entretiens | Tous | Le tableau de bord résume ; la page « Mes entretiens » liste tout |
| Barre de complétude écrite à la main avec `role="progressbar"` | `mat-progress-bar` | Valeur et libellé accessibles explicites ; un composant de plus pour une barre statique |

## 4. Questions d'entretien

**« Où se fait la correspondance entre statut interne et statut candidat ? »** Dans un seul enum de l'API du module Candidatures (`CandidateStatus.of`), utilisé par la vue candidat, la chronologie et le tableau de bord. Une seule table de correspondance, testée.
