# US-30 — Lister les candidatures

Phase 6 · MUST · 5 points · dépend de US-27 · réf. F-APP-04, RG-05, RG-25

## 1. Objectif et critères

| Critère d'acceptation | Preuve |
| --- | --- |
| Seulement les candidatures de mon entreprise, paginées, plus récentes d'abord | `RecruiterApplicationIT.listShowsOnlyMyCompanyNewestFirst` |
| Filtres offre, statut, compétence, période combinés, dans l'URL | `filtersAreCombined` ; `applicationParams` (spec) ; `ApplicationListPage` lit ses filtres dans les paramètres de requête |
| Recherche par nom | Même test : sans casse ni accents (« elalami » trouve « Élalami »), « nom prénom » comme « prénom nom » |
| 20 lignes → nombre de requêtes indépendant du nombre de lignes | `ApplicationListQueriesIT.listsUseAFixedNumberOfQueries` : proxy JDBC qui compte les requêtes (fuseau de l'entreprise, total, page : le même nombre quelle que soit la taille) |
| (ajout) Tri en liste blanche, jamais par score par défaut | `ApplicationSortTest` |

## 2. Choix techniques

| Choix | Alternative écartée | Raison |
| --- | --- | --- |
| SQL natif (`RecruiterApplicationSearch`) joignant `job_offer`, `app_user`, `candidate_profile`, `candidate_skill` | Specifications JPA (prévues par l'architecture) ; filtrage via les API des modules | `Application` ne référence les autres modules que par identifiant : aucune relation JPA à suivre. Passer par les API obligerait à échanger de longues listes d'identifiants ou à paginer en mémoire |
| **Exception documentée** aux frontières de modules, en lecture seule | Projection dénormalisée dès maintenant | Une seule classe concernée, couverte par les tests ; si les modules devenaient des services, une projection alimentée par événements la remplacerait |
| Total puis page (2 requêtes) + fuseau de l'entreprise (1) | `count(*) OVER ()` | Le total reste exact même pour une page au-delà des résultats |
| `strpos` sur `lower(immutable_unaccent(...))` | `ILIKE '%…%'` | Les `%` et `_` saisis restent littéraux ; accents retirés **avant** `lower` (en collation C, `lower` ne connaît que l'ASCII) |
| Dates « du / au » en jours du fuseau de l'entreprise, « au » inclus | Instants UTC | Le recruteur pense en jours locaux |
| Compétence : le candidat les déclare **toutes** | Au moins une | Un filtre qui resserre ; même règle que la recherche d'offres |
| Filtre de compétence sans création (`allowCreate=false`) | Autocomplétion standard | Un filtre ne doit pas enrichir le référentiel |

## 3. Commande

```bash
./mvnw verify -Dit.test=ApplicationListQueriesIT
```

## 4. Questions d'entretien

**« Ce module lit les tables d'autres modules : n'est-ce pas contraire à votre architecture ? »** Si, et c'est volontaire, limité et écrit dans le code : lecture seule, une classe. Les écritures passent toutes par les API. Le coût de la pureté (listes d'identifiants, pagination en mémoire) aurait été supérieur au bénéfice dans un monolithe.

**« Comment testez-vous l'absence de N+1 ? »** En enveloppant la `DataSource` dans un proxy qui compte `prepareStatement`, puis en comparant une page de 2 lignes et une page de 20. Le compteur voit Hibernate et JdbcClient.
