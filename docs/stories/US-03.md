# US-03 — Erreurs uniformes

Phase 2 · MUST · 2 points · dépend de US-01

## 1. Objectif et critères

Toute erreur de l'API, quelle que soit son origine, arrive au frontend dans le même format Problem Details (RFC 9457), avec un `code` stable et un identifiant de corrélation que l'on retrouve dans les logs.

| Critère d'acceptation | Preuve |
| --- | --- |
| Champs invalides → 400 `VALIDATION_FAILED` avec la liste des champs | `GlobalExceptionHandlerTest.invalidFieldsGive400WithTheListOfFields`, `invalidRequestParameterGives400` |
| Exception imprévue → 500 `INTERNAL_ERROR` sans trace, identifiant de corrélation aussi dans les logs | `unexpectedErrorGives500WithoutTechnicalDetail` (vérifie la réponse et la sortie des logs) |
| Exception métier → code et statut du catalogue | `invalidStateGives409WithItsOwnCode`, `businessRuleGives422WithDetailsAtTopLevel`, `ErrorCatalogTest` |

## 2. Fichiers

| Fichier | Rôle |
| --- | --- |
| `shared/domain/ErrorCode.java` | Les 32 codes du catalogue (dont 3 ajoutés par l'API et 3 techniques : 405, 406, 415) |
| `shared/domain/DomainException.java` et ses 3 sous-classes | Exceptions métier : un code, un message pour l'utilisateur, des détails éventuels |
| `shared/web/ErrorCatalog.java` | Code → statut HTTP, titre, URI de type |
| `shared/web/ApiProblem.java` | Corps JSON de toute erreur |
| `shared/web/GlobalExceptionHandler.java` | Traduction unique exception → réponse |
| `shared/web/CorrelationIdFilter.java` | Identifiant de corrélation : en-tête, MDC, réponse |
| `application.yml` | `logging.pattern.level` affiche l'identifiant dans chaque ligne de log |
| `GlobalExceptionHandlerTest`, `ErrorCatalogTest` | Tests |
| `docs/analyse-fonctionnelle.md` §7 | Catalogue complété (INVALID_STATE, INVALID_CURRENT_PASSWORD, JOB_NOT_PUBLISHABLE, codes techniques) |

## 3. Choix techniques

| Choix | Alternative écartée | Raison |
| --- | --- | --- |
| Le domaine porte un code, la couche web choisit le statut HTTP | Exceptions annotées `@ResponseStatus` | Le domaine reste indépendant du protocole ; le catalogue est en un seul endroit |
| `switch` sans `default` dans `ErrorCatalog` | `Map<ErrorCode, HttpStatus>` | Un nouveau code non traduit ne compile pas : l'oubli est impossible, pas seulement testé |
| Classe `ApiProblem` dédiée | `ProblemDetail` de Spring | Les propriétés additionnelles (`code`, `missing`…) de `ProblemDetail` dépendent d'un mix-in Jackson dont l'enregistrement avec Jackson 3 n'est pas documenté clairement ; une classe explicite garantit la forme exacte du contrat |
| Hériter de `ResponseEntityExceptionHandler` | Écrire un handler par exception MVC | Spring y gère déjà une quinzaine d'exceptions (405, 415, 404 de route…) ; on ne remplace que le corps |
| `errors` toujours présent (liste vide) | Champ absent hors validation | Le frontend n'a pas à tester son existence |
| Identifiant client accepté s'il respecte `[A-Za-z0-9-]{8,64}` | Accepter n'importe quelle valeur | Une valeur libre irait dans les logs : risque d'injection de fausses lignes |
| 404 pour une route inconnue au même format | Page d'erreur par défaut | Une seule forme d'erreur, même pour une faute de frappe dans l'URL |

## 4. Commandes

```bash
cd backend
./mvnw test -Dtest='GlobalExceptionHandlerTest,ErrorCatalogTest'
./mvnw spring-boot:run
curl -i http://localhost:8080/api/v1/inexistant      # 404 application/problem+json, en-tête X-Correlation-Id
```

## 5. Erreurs probables

| Symptôme | Cause | Solution |
| --- | --- | --- |
| Le test 500 échoue sur la sortie des logs | Le motif de log ne contient pas le MDC | Vérifier `logging.pattern.level` dans `application.yml` |
| Réponse 404 en HTML ou JSON Spring par défaut pour une route inconnue | Le `GlobalExceptionHandler` n'est pas chargé | Il doit être dans un paquet scanné (`com.smartrecruit.shared.web`) |
| Les erreurs 401/403 n'ont pas encore ce format | Normal : elles viennent de Spring Security | Traitées en phase 3 par un point d'entrée et un gestionnaire d'accès refusé dédiés |

## 6. Questions d'entretien

**« Pourquoi un 409 et pas un 400 pour une transition interdite ? »** La requête est bien formée ; c'est l'état actuel de la ressource qui l'empêche. Le 400 dit « corrige ta requête », le 409 dit « la ressource a changé, recharge-la ».

**« Que renvoies-tu au client pour une erreur 500 ? »** Un message générique et l'identifiant de corrélation. La trace complète n'est que dans les logs : elle révélerait des noms de classes, de tables, parfois des données.

**« À quoi sert l'identifiant de corrélation ? »** À relier une erreur vue par l'utilisateur à toutes les lignes de log de sa requête. Il est accepté en entrée pour suivre une requête à travers plusieurs services.

**« Comment garantis-tu que le catalogue est complet ? »** Par le compilateur : les `switch` sur l'énumération n'ont pas de branche par défaut. Un test paramétré vérifie en plus quelques statuts clés du catalogue.
