# US-26 — Détail d'une offre

Phase 5 · MUST · 2 points · dépend de US-23 · réf. F-JOB-05

## 1. Objectif et critères

| Critère d'acceptation | Preuve |
| --- | --- |
| Informations publiques, entreprise, compétences ; salaire seulement s'il est public | `JobSearchIT.detailShowsCompanyCategoryAndSkills`, `hiddenSalaryIsNeverShownNorUsableAsAFilter` ; `formatSalary` (spec) |
| Candidat ayant déjà postulé → lien vers sa candidature | **Partiel** : le champ `alreadyApplied` existe (toujours `null`/`false` en phase 5) ; le bouton « Postuler » est affiché désactivé. Le lien sera branché avec US-27 (phase 6) |
| Offre non publiée ou expirée → 404 pour le public | `draftDetailIsNotFound` ; même filtre que la recherche (`isOpen`) |

## 2. Choix techniques

| Choix | Alternative écartée | Raison |
| --- | --- | --- |
| Endpoint public avec `Optional<CurrentUser>` | Deux endpoints (public / candidat) | Une seule URL partageable ; le candidat connecté reçoit en plus `alreadyApplied` |
| 404 (pas 410) pour une offre expirée | 410 Gone | Même réponse que pour une offre inexistante : pas d'information sur les brouillons |
| Description en texte brut avec retours à la ligne (`white-space: pre-line`) | HTML riche | Aucun risque XSS ; un éditeur riche avec assainissement pourra venir plus tard |

## 3. Question d'entretien

**« Pourquoi `alreadyApplied` peut-il valoir `null` ? »** Trois états : `null` pour un visiteur ou un recruteur (la question n'a pas de sens), `false` / `true` pour un candidat. Le frontend n'a pas à deviner le rôle.
