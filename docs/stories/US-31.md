# US-31 — Dossier de candidature

Phase 6 · MUST · 5 points · dépend de US-30, US-52 · réf. F-APP-05, F-CAND-05, RG-05, RG-12

## 1. Objectif et critères

| Critère d'acceptation | Preuve |
| --- | --- |
| Profil, CV envoyé, historique, notes, entretiens, résultats IA | `RecruiterApplicationIT.dossierShowsTheProfileTheResumeSentAndTheAllowedTransitions` ; page `ApplicationDossierPage` (onglets Profil, Historique). **Partiel** : `interviews`, `notesCount` et `ai` existent dans la réponse mais restent vides jusqu'aux phases 7 et 8 |
| Candidature d'une autre entreprise → 404 | `applicationOfAnotherCompanyIsNotFound` (dossier, historique, CV, changement de statut ; rien n'est modifié) |
| CV du dossier = version envoyée ; téléchargement audité | Même premier test : après un nouveau CV, le dossier sert toujours `cv-salma.pdf`, en `attachment` et `no-store`, avec une ligne `RESUME_DOWNLOADED` |

## 2. Choix techniques

| Choix | Alternative écartée | Raison |
| --- | --- | --- |
| `ApplicationAccess.forRecruiter` : candidature puis offre, entreprise comparée à celle du token | Filtre dans chaque méthode | Un seul endroit pour la règle, utilisé par les écritures et les lectures |
| 404 hors périmètre | 403 | Ne confirme pas l'existence d'une candidature d'un concurrent (F-APP-05) |
| Profil lu par `CandidateDirectory.dossier` | Jointures sur les tables du profil | Le profil a de nombreuses sous-listes déjà assemblées par le module Candidats |
| `allowedTransitions` calculées par le serveur | Table des transitions dupliquée en TypeScript | Une seule source de vérité ; RG-33 (entretien terminé) n'est connu que du serveur |
| Transaction **en écriture** pour le téléchargement | `readOnly` | L'audit y est inséré ; PostgreSQL refuse un INSERT dans une transaction en lecture seule |

## 3. Question d'entretien

**« Pourquoi auditer un téléchargement de CV ? »** C'est l'accès à une donnée personnelle sensible. Le journal permet de répondre à « qui a consulté mon CV ? » (RGPD, loi 09-08).
