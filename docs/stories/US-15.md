# US-15 — Compétences du référentiel

Phase 4 · MUST · 5 points · dépend de US-13 · réf. F-CAND-02

## 3. Choix techniques

| Choix | Alternative écartée | Raison |
| --- | --- | --- |
| « Obtenir ou créer » avec forme normalisée unique | Création libre | Pas de doublon « spring boot » / « Spring  Boot » ; la base garantit l'unicité (`uk_skill_normalized_name`) |
| Création dans sa propre transaction (`REQUIRES_NEW`), relecture après conflit | Une transaction englobante | PostgreSQL annule toute la transaction après une violation de contrainte : seule une petite transaction séparée permet de relire la compétence créée en même temps par un autre |
| Alias consultés avant les noms | Noms seulement | « springboot » ou « k8s » mènent à la compétence canonique ; prépare la fusion (US-51) et l'IA |
| Index `varchar_pattern_ops` partiel sur les compétences actives | Index B-tree standard | Un `LIKE 'spr%'` n'utilise un index B-tree que s'il est créé avec cette classe d'opérateurs |
| `%` et `_` échappés dans la recherche | Recherche brute | « 100% » ne doit pas devenir « tout ce qui commence par 100 » |
| Remplacement en bloc de la liste (`PUT`) | Un appel par compétence | Petite liste éditée dans un formulaire ; une seule transaction atomique |
| Erreur de champ avec chemin (`skills[2].skillId`) | Message global | Le frontend place l'erreur sous la bonne ligne (`applyServerErrors` traduit le chemin) |
| Jeton `SKILL_SEARCH` fourni par `core` | Autocomplétion dans une feature | Le composant sert aussi aux offres (phase 5) et reste dans `shared` sans appel HTTP |

## 4. Erreurs probables

| Symptôme | Cause | Solution |
| --- | --- | --- |
| 400 `skills[0].skillId` « inconnue ou désactivée » | Compétence désactivée par l'admin entre la recherche et l'enregistrement | Choisir une autre compétence |
| Doublon apparu malgré tout | Variante non couverte par la normalisation (« Spring-Boot ») | Fusion par l'admin (US-51), qui crée un alias |

## 5. Questions d'entretien

**« Que se passe-t-il si deux candidats créent “Quarkus” au même moment ? »** Les deux voient qu'elle n'existe pas ; le premier INSERT réussit, le second viole l'index unique. Sa petite transaction est annulée, le service relit et renvoie la compétence créée par l'autre : un seul « Quarkus ».
