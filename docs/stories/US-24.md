# US-24 — Offres de mon entreprise

Phase 5 · MUST · 3 points · dépend de US-21 · réf. F-JOB-06

## 1. Objectif et critères

| Critère d'acceptation | Preuve |
| --- | --- |
| Toutes les offres de l'entreprise, tous statuts, avec les candidatures par statut | `JobOfferIT.companyListHidesArchivedOffersUnlessAsked` ; colonne « Candidatures » de `JobListPage` (`totalApplications`, spec) |
| Filtre de statut ; ARCHIVED masquées par défaut | Même test (`?status=ARCHIVED` les montre) ; filtre « Toutes sauf archivées » de l'écran |

## 2. Choix techniques

| Choix | Alternative écartée | Raison |
| --- | --- | --- |
| `GET /company/jobs` séparé de `GET /jobs` | Un seul endpoint avec un paramètre « mine » | Règles de sécurité et forme de réponse différentes (brouillons, compteurs) |
| Compteurs via `JobApplicationStats` (module `application`, phase 6) consommée par `ObjectProvider` | Jointure SQL sur une table pas encore créée | Le module `job` ne dépend pas de l'implémentation ; en phase 5, les compteurs sont vides |
| Filtre et page dans l'URL, `httpResource` | État local du composant | Lien partageable, retour arrière du navigateur cohérent (architecture frontend §8) |

## 3. Question d'entretien

**« Pourquoi masquer les archives par défaut plutôt que les supprimer ? »** Les candidatures et l'audit y font référence ; l'archive sort l'offre du quotidien sans perdre l'historique.
