# US-56 — Données de démonstration

Phase 11 · MUST · 3 points · dépend de US-42 · réf. E (volume de démonstration)

## 1. Objectif et critères

| Critère d'acceptation | Preuve |
| --- | --- |
| Profil `demo` sur une base vide : entreprises, recruteurs, candidats fictifs, offres, candidatures à tous les statuts, entretiens | `DemoDataIT.theDemoDatasetIsCompleteConsistentAndFictitious` : les 8 statuts de candidature et les 4 statuts d'offre présents, une entreprise désactivée, au moins 3 entretiens dans les 7 jours, au moins 5 candidatures récentes, 12 CV PDF présents dans le stockage ; démarrage réel en `dev,demo` puis en `prod,demo` |
| Un identifiant de démonstration par rôle dans le README | README, « Comptes de démonstration » ; le test vérifie que les trois comptes se connectent avec le mot de passe documenté |
| Aucune donnée réelle | Entreprises inventées, domaines `.example` (RFC 2606), téléphones en `+212 6 00 00 xx 00`, employeurs fictifs dans les CV ; vérifié par le test |
| Au moins une entreprise de démonstration (repris d'US-02) | 4 entreprises |

Cohérence vérifiée par le même test : chaque candidature commence par `CREATED` et son dernier changement de statut correspond à son statut actuel ; aucune proposition ni embauche sans entretien terminé (RG-33) ; tout rejet a un motif (RG-14). `nothingIsLoadedWhenTheDatabaseAlreadyHasCompanies` : rien n'est chargé si une entreprise existe.

## 2. Contenu

4 entreprises (Atlasia Tech, Novaterra Conseil, Riad Logistique, Saffran Studio désactivée), 5 recruteurs dont un désactivé, 12 candidats avec profil complet et CV, 10 offres (brouillon, publiées, clôturées, archivée), 22 candidatures avec leur historique, 7 entretiens (à venir et terminés avec avis), 5 notes. Les dates sont relatives au démarrage : les indicateurs « 7 jours », « 30 jours » et « entretiens à venir » ont toujours du contenu.

## 3. Fichiers

Module `demo` : `DemoDataSeeder` (déclenché sur `ApplicationReadyEvent`, profil `demo`), `DemoWriter` (écritures SQL qui respectent les règles), `DemoData` (contenu fictif), `DemoPdf` (CV en PDF texte) ; `application-demo.yml`.

## 4. Choix techniques

| Choix | Alternative écartée | Raison |
| --- | --- | --- |
| Écriture SQL directe, règles reproduites | Appels aux services métier | Les services fixent les dates à « maintenant » et refusent un entretien dans le passé : impossible de fabriquer un historique de plusieurs semaines |
| Migration Flyway séparée (`db/demo`) | — | Un CV doit aussi exister comme fichier dans le stockage, et les mots de passe doivent être hachés au démarrage : du Java est nécessaire |
| Chargement seulement si aucune entreprise n'existe, en une transaction | Chargement à chaque démarrage | Redémarrer ne duplique rien ; une base de production n'est jamais touchée par erreur ; en cas d'échec, la base reste vide |
| Pas de résultats d'IA fabriqués | Faux scores insérés | Un score affiché doit venir du calcul et du modèle (RG-27) ; les CV de démo sont de vrais PDF lisibles, l'analyse se lance dès qu'Ollama a son modèle |
| Test en transaction annulée, profil `demo` non activé | Base dédiée | Les autres tests d'intégration partagent la base ; rien ne doit y rester |
