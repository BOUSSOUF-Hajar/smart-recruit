# US-04 — Squelette frontend

Phase 2 · MUST · 3 points · sans dépendance

## 1. Objectif et critères

Un projet Angular 22 structuré en `core`, `shared`, `layouts` et `features`, avec Angular Material, des intercepteurs HTTP et des frontières entre dossiers vérifiées par ESLint.

| Critère d'acceptation | Preuve |
| --- | --- |
| Mise en page avec en-tête et zone de contenu, Angular Material configuré | `app.routes.spec.ts` (« affiche la mise en page publique ») |
| Route inconnue → page « introuvable » | `app.routes.spec.ts` (« affiche la page introuvable ») |
| Erreur HTTP → notification générique par un intercepteur | `error.interceptor.spec.ts` (6 cas) |

Vérifié dans cet environnement : `npm run lint`, `npm run format:check`, `npm run test:ci` (14 tests) et `npm run build` passent.

## 2. Arborescence créée

```
frontend/
├── angular.json            # locale fr, proxy de dev, polices hébergées localement
├── proxy.conf.json         # /api → http://localhost:8080 en développement
├── eslint.config.js        # règles Angular + frontières core/shared/features
└── src/app/
    ├── app.config.ts       # routeur, HttpClient (Fetch) + intercepteurs, ErrorHandler, icônes
    ├── app.routes.ts       # PublicLayout, redirection '' → /jobs, '**' → /not-found
    ├── core/
    │   ├── errors/         # ApiError, NotificationService, GlobalErrorHandler
    │   └── http/           # correlationInterceptor, errorInterceptor
    ├── shared/ui/empty-state/
    ├── layouts/public-layout/
    └── features/public/    # public.routes.ts, pages jobs (provisoire), not-found, forbidden
```

## 3. Choix techniques

| Choix | Alternative écartée | Raison |
| --- | --- | --- |
| Projet généré par `ng new` (Angular CLI 22.2.3) puis `ng add` | Fichiers écrits à la main | Configuration à jour et identique à ce qu'un recruteur connaît |
| Polices Roboto et Material Symbols installées par npm | Liens Google Fonts ajoutés par `ng add` | La CSP prévue (`'self'`) les bloquerait ; aucune requête vers un tiers, rien ne dépend d'Internet au build |
| Intercepteurs fonctionnels (`HttpInterceptorFn`) | Classes `HttpInterceptor` | Forme recommandée depuis Angular 15, plus courte, testable sans classe |
| Notification globale seulement pour réseau, 5xx, 429 et 403 | Notifier toute erreur | Les 400/404/409/422 sont mieux expliquées par l'écran (sous le champ, dans un bandeau) |
| `toApiError` tolère un corps non conforme | Supposer toujours le bon format | Un proxy ou Nginx peut répondre en HTML (502) |
| Règle ESLint `no-restricted-imports` par dossier | `eslint-plugin-boundaries` | Suffit pour les 3 règles utiles, sans dépendance de plus |
| `$localize` et attributs `i18n`, locale source `fr` | Textes en dur | Décision G-9 : traduction possible plus tard sans réécrire les gabarits |
| Strict TypeScript + `strictTemplates` | Défauts | Erreurs de typage dans les gabarits détectées à la compilation |

Point d'attention : la police d'icônes Material Symbols complète pèse 3,9 Mo (chargée une fois, mise en cache). Si le poids devient gênant, on passera à des icônes SVG ciblées.

## 4. Commandes

```bash
cd frontend
npm ci
npm start                 # http://localhost:4200, /api relayé vers le backend
npm run lint
npm run test:ci
npm run build
```

Node.js 22.22.3+ ou 24.15+ est requis par Angular CLI 22.

## 5. Erreurs probables

| Symptôme | Cause | Solution |
| --- | --- | --- |
| `The Angular CLI requires a minimum Node.js version…` | Node trop ancien | Installer Node 24 LTS |
| `Inlining of fonts failed` au build | Un lien Google Fonts a été réintroduit dans `index.html` | Utiliser les polices de `angular.json` → `styles` |
| Icônes affichées comme du texte (« search_off ») | Classe de police d'icônes non définie | Vérifier `MAT_ICON_DEFAULT_OPTIONS` dans `app.config.ts` |
| Erreur ESLint `no-restricted-imports` | Un fichier de `shared` ou `core` importe une feature | Déplacer le code vers le bon dossier ; ne pas désactiver la règle |

## 6. Questions d'entretien

**« Pourquoi un intercepteur pour les erreurs ? »** Pour traiter une fois, au même endroit, ce qui est commun à tous les appels : conversion en erreur typée et notification des pannes générales. Chaque écran ne gère plus que ses propres cas.

**« Dans quel ordre s'exécutent les intercepteurs ? »** Dans l'ordre de la liste pour la requête, dans l'ordre inverse pour la réponse. L'intercepteur d'erreur est placé avant ceux de rafraîchissement et d'authentification (phase 3) : il ne voit que l'erreur finale, après une éventuelle tentative de renouvellement de session.

**« Pourquoi des composants autonomes et OnPush ? »** Ce sont les défauts d'Angular 22. Chaque composant déclare ses dépendances, et avec les signaux, OnPush ne revérifie que ce qui a changé.
