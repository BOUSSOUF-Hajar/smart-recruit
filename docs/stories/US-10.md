# US-10 — Accès selon le rôle

Phase 3 · MUST · 3 points · dépend de US-07 · réf. ENF-SEC-01, ENF-SEC-02, matrice C.2

## 1. Objectif et critères

La matrice de `docs/api.md` §11 est appliquée dans l'ordre par Spring Security, avec refus par défaut ; le frontend évite de télécharger les espaces interdits.

| Critère d'acceptation | Preuve |
| --- | --- |
| Candidat sur un endpoint recruteur ou admin → 403 `ACCESS_DENIED` | `SecurityMatrixIT` |
| Non connecté sur un endpoint protégé → 401 | `SecurityMatrixIT`, `AuthFlowIT.meRequiresAValidToken` |
| URL `/recruiter/...` tapée par un candidat → redirection vers son tableau de bord | `guards.spec` (`roleGuard`), `app.routes.spec` |
| Chaque endpoint vérifié pour chaque rôle | `SecurityMatrixIT` : 30 lignes × 4 profils (anonyme + 3 rôles) |

## 2. Fichiers

| Fichier | Rôle |
| --- | --- |
| `shared/security/SecurityConfig.java` | Règles d'accès, en-tête CSP, sans session ni CSRF |
| `ApiAuthenticationEntryPoint`, `ApiAccessDeniedHandler`, `shared/web/ProblemResponseWriter` | 401 et 403 au format Problem Details |
| `CurrentUser`, `CurrentUserArgumentResolver`, `SecurityWebConfig` | Utilisateur courant injecté dans les contrôleurs |
| Frontend `core/guards/*`, `app.routes.ts`, `layouts/app-layout/*` | Guards `canMatch`, espaces chargés à la demande, navigation par rôle |

## 3. Choix techniques

| Choix | Alternative écartée | Raison |
| --- | --- | --- |
| Règles centralisées + `anyRequest().denyAll()` | `@PreAuthorize` sur chaque méthode | Toute la matrice se lit en un endroit et un endpoint oublié est refusé |
| Test par critère d'erreur (`code`) plutôt que par statut | Statut seul | Un endpoint pas encore écrit répond 404 : on vérifie la décision de sécurité, pas le contrôleur |
| CSRF désactivé | Jeton CSRF | Le token voyage dans un en-tête que le navigateur n'ajoute jamais seul ; les deux endpoints à cookie sont en `SameSite=Strict` |
| Pas de CORS | `@CrossOrigin` | Même origine (proxy en dev, Nginx en prod) |
| Guards `canMatch` | `canActivate` | Le code d'un espace interdit n'est pas téléchargé |
| `AppLayout` chargé à la demande | Import direct | Bundle initial sous le budget de 500 kB (498 kB) |

## 4. Erreurs probables

| Symptôme | Cause | Solution |
| --- | --- | --- |
| `POST /jobs/{id}/applications` refusé aux candidats | Règle 4 (`/jobs/**` RECRUITER) placée avant la règle 3 | Respecter l'ordre ; `SecurityMatrixIT` le détecte |
| `/` affiche un gabarit vide | Route vide avec enfants (`AppLayout`) placée avant la route publique | Routes publiques en premier |
| 403 au lieu de 401 pour un anonyme | `AccessDeniedHandler` utilisé seul | Déclarer aussi l'`AuthenticationEntryPoint` dans `exceptionHandling` |

## 5. Questions d'entretien

**« Les guards Angular suffisent-ils ? »** Non : ils améliorent l'expérience. Tout se contourne côté client ; la sécurité est dans l'API, puis dans le contrôle de propriété des services (RG-05, RG-06).

**« Différence entre 401 et 403 ? »** 401 : on ne sait pas qui vous êtes. 403 : on sait, et ce n'est pas permis.
