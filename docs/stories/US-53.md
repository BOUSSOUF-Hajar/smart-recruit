# US-53 — Consulter le journal d'audit

Phase 10 · MUST · 3 points · dépend de US-47, US-52 · réf. F-ADM-06, RG-24

## 1. Objectif et critères

| Critère d'acceptation | Preuve |
| --- | --- |
| Filtres période, utilisateur, action, résultat ; paginé, plus récentes d'abord | `AuditLogConsultationIT.filtersByActorActionResultAndPeriodNewestFirst` (auteur + action, résultat + période, période passée vide, période incohérente → 400, liste des actions) ; `audit-params.spec` (jours locaux convertis en instants, fin de période incluse) |
| Aucune action ne modifie ni ne supprime une entrée | `theJournalCanNeitherBeModifiedNorDeleted` : `PUT`/`DELETE` → 405 ; un `UPDATE` ou `DELETE` SQL direct est refusé par le déclencheur `trg_audit_log_immutable` (V14) ; l'écran n'a aucune action sur une entrée |

Complément : réservé aux admins (`onlyAnAdminReadsTheJournal`, `SecurityMatrixIT`).

## 2. Fichiers

- Backend : `V14__administration.sql` (déclencheur, index `ix_audit_log_result`) ; `audit/infrastructure/AuditLogSearch` ; `audit/web/AdminAuditController`.
- Frontend : `audit/audit-log.page.ts`, `audit/audit-params.ts`.

## 3. Choix techniques

| Choix | Alternative écartée | Raison |
| --- | --- | --- |
| Requête construite avec les seuls filtres présents | `(:p IS NULL OR col = :p)` | PostgreSQL choisit l'index adapté (période, auteur, action, résultat) ; et un paramètre nul non typé ne passe pas avec le pilote |
| Nom de l'auteur lu par jointure sur `app_user` | Copie du nom dans chaque entrée | La clé étrangère existe déjà ; lecture seule ; l'email copié reste pour les connexions échouées sans compte |
| Déclencheur qui refuse UPDATE et DELETE, sauf la mise à nul de l'auteur | Convention seule | Même protection que l'historique des candidatures ; l'exception laisse fonctionner `ON DELETE SET NULL` si un compte est un jour supprimé (droit à l'effacement) |
| Bornes envoyées en instants ISO, calculées dans le fuseau du navigateur | Dates simples interprétées en UTC par le serveur | RG-32 : « le 3 » est la journée du 3 pour l'admin, pas celle de Greenwich |
| Détails JSON affichés repliés (`<details>`) | Colonnes dédiées | Le contenu varie selon l'action ; il ne contient jamais de secret (`AuditDetailsPolicy`, US-52) |

## 4. Question d'entretien

**« Un admin malveillant peut-il effacer ses traces ? »** Pas par l'application : aucun endpoint d'écriture. Pas non plus par une requête SQL de l'utilisateur applicatif : le déclencheur refuse. Il faudrait être propriétaire de la base et désactiver le déclencheur, ce qui relève de l'administration système (comptes séparés en production, sauvegardes).
