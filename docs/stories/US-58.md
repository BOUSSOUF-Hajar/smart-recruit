## 3. Choix techniques

| Choix | Alternative écartée | Raison |
| --- | --- | --- |
| Ajouter springdoc | Assumer `docs/api.md` comme seule référence | Prévu par le cahier des charges (F.1) et l'architecture backend ; un recruteur technique essaie l'API en un clic |
| Documentation sous `/api/docs` | Chemins par défaut `/v3/api-docs`, `/swagger-ui.html` | Seul `/api/` est relayé par Nginx : la documentation passe par la même origine, sans nouvelle règle de proxy |
| Coupée par défaut, activée par les profils `dev` et `demo` | Activée partout | Ne pas décrire la surface d'attaque en production ; avec `prod,demo`, le profil `demo`, lu en dernier, l'emporte |
| Chaîne de sécurité dédiée, examinée en premier | Assouplir la CSP de toute l'API | L'API garde `default-src 'none'` ; seule la documentation reçoit la politique de Nginx (`'self'`) |
| `location ^~ /api/` | Ajouter des exceptions à la règle des fichiers statiques | Tout `/api/` va au backend, quelle que soit l'extension du chemin |
| Exigence `bearer` globale dans la description | Annoter chaque contrôleur | Une ligne au lieu de dizaines d'annotations ; Swagger UI n'envoie le jeton que s'il a été saisi |
| Captures prises par un script Playwright versionné | Captures manuelles | Mêmes écrans, même taille (1440 × 900), mêmes données à chaque fois ; l'interface change, on relance une commande |
| Navigateur installé (`PW_CHROMIUM_PATH`) | Chromium de Playwright | Aucun téléchargement de plus sur une connexion lente ; la configuration le permettait déjà (US-57) |
| Pas de capture du journal d'audit | La montrer quand même | Les données de démonstration n'y écrivent rien : elle ne montrait que les connexions du script |
| Traduction des paginateurs fournie par `AppLayout` et la page de recherche publique | La fournir dans `app.config` | Mesuré : importer le paginateur au démarrage ajoutait 185 ko (36 ko transférés) au bundle initial, soit + 33 % ; fournie par les écrans chargés à la demande, elle ne coûte rien au premier affichage |

Auparavant, le 23 octobre 2026, **aucune vérification automatique n'avait pu tourner** :

- pas de JDK 25 installé (seulement les versions 17 et 21), donc ni `./mvnw verify` ni `./mvnw spotbugs:check` ;
- connexion à environ 5 Ko/s : Spring Modulith, springdoc et les images Docker ne peuvent pas être téléchargés ; `frontend/node_modules` est absent, donc ni lint, ni Vitest, ni Playwright ;
- le wrapper Maven n'a pas pu être généré (délai de lecture dépassé sur Maven Central).

Ce qui a été vérifié à la main : version de springdoc compatible (3.1.1, parent Spring Boot 4.1.0, lu sur Maven Central) ; ordre des chaînes de sécurité ; 404 attendu quand la documentation est coupée (`GlobalExceptionHandler` hérite de `ResponseEntityExceptionHandler`, qui traduit `NoResourceFoundException`).

Points à surveiller au premier passage réel :

- chemin des ressources de Swagger UI : `/api/docs/swagger-ui/index.html` est déduit de `springdoc.swagger-ui.path` ; les tests le vérifient ;
- CSP : Swagger UI n'utilise pas de script en ligne, mais une éventuelle évaluation de code dans le bundle (`'unsafe-eval'`) ferait échouer `api-docs.e2e.ts`, qui refuse toute violation CSP. Dans ce cas, il faudrait un assouplissement limité à `/api/docs`, à documenter ici.

## 6. Questions d'entretien

**« Pourquoi la documentation de l'API est-elle coupée en production ? »** Elle décrit toute la surface d'attaque : chemins, paramètres, schémas. Le contrat reste public dans le dépôt (`docs/api.md`) pour qui en a besoin, mais le serveur de production n'a pas à le servir.

**« Pourquoi une seconde chaîne de filtres Spring Security ? »** Chaque chaîne a sa propre politique. L'API renvoie du JSON et n'a besoin d'aucune ressource (`default-src 'none'`) ; Swagger UI est une page qui charge ses scripts et ses styles. Une chaîne dédiée, limitée à `/api/docs/**` et examinée en premier, évite d'affaiblir la politique de l'API.

**« Comment avez-vous découvert que springdoc manquait ? »** En confrontant la documentation au code pendant la phase 12 : `api.md` annonçait Swagger UI, mais aucune dépendance ni configuration ne l'implémentait. C'est le rôle de cette dernière phase : vérifier que ce qui est écrit est vrai.

**« Pourquoi ne pas avoir traduit le paginateur dans la configuration globale ? »** Parce que je l'ai mesuré : `MatPaginatorIntl` importé dans `app.config` faisait entrer tout le paginateur dans le bundle initial, 185 ko de plus pour un visiteur qui ne voit peut-être aucune liste. Fourni par le gabarit des espaces connectés, chargé à la demande, il a le même effet sans coût au démarrage. Le build affiche la taille du bundle initial : c'est le chiffre à surveiller à chaque changement de configuration globale.

**« À quoi ont servi les captures, au-delà du README ? »** À regarder l'application comme un visiteur : elles ont révélé deux défauts qu'aucun test ne voyait, un paginateur resté en anglais et une espace manquante. Les tests vérifient ce qu'on a pensé à vérifier ; une revue visuelle trouve le reste.
